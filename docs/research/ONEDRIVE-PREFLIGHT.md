# OneDrive Win32 preflight research

**Status:** read-only detector design for Windows 11 Pro/Pro N; no uninstall or unlink action is included. Reviewed 2026-10-16. This slice has no network calls and does not read user file contents.

## Microsoft sources and applicability

- [Turn off, disable, or uninstall OneDrive](https://support.microsoft.com/en-us/onedrive/turn-off-disable-or-uninstall-onedrive) documents Windows 10/11 unlinking through the OneDrive account settings and uninstalling through Installed apps. It also notes that OneDrive is built into some Windows versions and may not be uninstallable. This supports keeping unlink and uninstall as deliberate user-mediated steps, not deriving a command from a registry string.
- [Save disk space with OneDrive Files On-Demand for Windows](https://support.microsoft.com/en-us/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows) explains that online-only files do not occupy local file data until opened, while “Always keep on this device” downloads files for offline use. A process check, account registry entry, or folder path cannot prove file hydration. This preflight therefore reports hydration as `unknown` and does not enumerate files, inspect placeholder attributes, open files, or trigger downloads.
- [Redirect and move Windows known folders to OneDrive](https://learn.microsoft.com/en-us/sharepoint/redirect-known-folders) describes moving Desktop, Documents, and Pictures into OneDrive, including silent policy-driven moves and caveats for folders previously redirected elsewhere. It supports checking the three current known-folder paths against roots registered for the current user's OneDrive accounts, while treating this path comparison only as a signal and not proof that all contents are backed up.
- [Registry keys affected by WOW64](https://learn.microsoft.com/en-us/windows/win32/winprog64/shared-registry-keys) lists `HKEY_CURRENT_USER\SOFTWARE` as shared on supported Windows versions, while `HKEY_LOCAL_MACHINE\SOFTWARE` is redirected. The collector therefore reads one current-user view and separate machine 64-bit/32-bit views; it avoids counting the same current-user registration twice.

## Detection contract

The detector reads uninstall registrations from the 64-bit and 32-bit machine views and one shared current-user view. It reads `DisplayName` while enumerating uninstall keys, then reads `Publisher` only for the exact display name `Microsoft OneDrive`; it reads uninstall command values only after both the exact display name and exact publisher `Microsoft Corporation` match. These are expected registry metadata checks, not signature or executable verification. A name match with another publisher is flagged for review but is not accepted as a matching registration. It exposes only the registry scope, whether uninstall command values exist, and which value names supplied that metadata. It never returns raw commands, executable paths, versions, unrelated publishers, account names, email addresses, IDs, tokens, or folder paths. A null or malformed registry provider result is an error and cannot become an absent-install result.

It reports the exact `OneDrive` process as running or not running, but that is not evidence of an active sync. It reports whether OneDrive account registry metadata is present and always labels sign-in status unknown; registry metadata does not prove an authenticated account. Only the `UserFolder` value is read from each account key for root comparison; other account values are not read. Desktop/Documents/Pictures are compared with detected account roots without returning the paths. A missing known-folder path, incomplete or inaccessible registry data, or absence of comparison roots leaves the result unknown; missing evidence is never converted to absent or false. These observations do not establish account sign-in validity, sync completion, cloud backup completeness, file hydration, or uninstall safety.

Files On-Demand and hydration remain unknown/manual review. There are no recursive file scans, file content reads, placeholder hydration, account API calls, network requests, process termination, registry writes, unlink operations, or uninstall operations. The report always says manual review is required and does not claim the system is safe to uninstall.

## Later uninstall review gate

Before a separate opt-in uninstall proposal, a human must inspect OneDrive settings and confirm account/sync status, identify any organizational or personal account use, review the locations and contents of Desktop/Documents/Pictures, establish a trusted backup for needed data, and determine whether cloud-only placeholders must first be downloaded while OneDrive remains signed in. Any folder movement, unlinking, pause/quit, and uninstall must be separately described and user-confirmed. Use the supported Installed apps UI or another Microsoft-documented route after reviewing the exact installed product; never execute `UninstallString` or `QuietUninstallString` from registry data.

Uninstalling the client is separate from deleting a OneDrive cloud account or cloud files, but it can remove local access to cloud-only files until the client/account is available again. Known Folder Move and folder redirection state must be resolved deliberately. No automatic rollback is promised for unlinking, moving folders, or uninstalling; the preflight itself cannot prove a backup exists. Cloud files must never be deleted as part of application cleanup.
